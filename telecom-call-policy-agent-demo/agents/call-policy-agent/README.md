# Call Policy Agent

A demo agent for a fictional business-call policy lifecycle, built on the
Atlas Agent Engine SDK.

The agent helps a demo operator author, validate, dry-run, and (after explicit
human approval) activate call policies. All data is synthetic; individual call
decisions are made by a deterministic evaluator, not by an LLM.

**Features:** Human-in-the-loop (suspend/resume) · Deterministic evaluation

## What This App Includes

- A runnable SDK app with context-retrieval, drafting, validation, dry-run,
  and approval tools
- `agent.yaml`-driven runtime settings for feature flags
- A simple MongoDB-backed policy, version, approval, and audit store
- `agent.yaml` metadata for build and deploy workflows, with local-dev settings
  (service ports) in `dev.yaml`

Projects generated by `agentengine create` contain the selected LLM client;
every client reads `LLM_API_KEY` from `.env` or project secrets.

## Quick Start

```bash
cp env.example .env
agentengine dev up
```

Before you start the app, edit `.env` and:

- Leave `MONGODB_URI` empty for `agentengine dev`; set it only when running against
  your own MongoDB deployment
- Set `LLM_API_KEY` for the configured client in `.env`
- Review the LLM builder in `src/agent_call_policy_agent/llm.py`. To switch providers,
  update the import, constructor, and `MODEL`; the key remains `LLM_API_KEY`.

Once the local stack is running:

- Open the Playground UI at `http://localhost:3000` to chat with the agent
- The playground port is configured in `dev.yaml` under `services.playground.port`

Stop the local stack with:

```bash
agentengine dev down
```

See the repository-level `../../README.md` for the full walkthrough, tests,
reset instructions, and honest limitations.
